# AI 私教 Flutter UI 工作量评估

评估日期：2026-11-09。基于当前本地实现，尚未开始替换私教UI。以下是单人实施与常规验证估算，不是交付时间承诺。

## 结论

主聊天界面与流式展示的可用版本约6–10小时；复现当前全部私教功能并直接替换原入口约16–24小时（约2–3个完整工作日）。前者是完整目标的一部分，不是可以省略其余功能的等价替代。

已有Rust SSE/JNI、原生取消与请求代号、AiStreamSnapshot、五语状态、Flutter纯状态机和玻璃组件，因此无需重写HTTP/TLS、提示词或Room。主要工作转移到了桥接、交互与一致性验证。

| 工作 | 估算 | 具体范围 |
| --- | --- | --- |
| 原入口宿主、命令和状态订阅 | 3–4小时 | ViewModel继续持有请求；订阅先快照后增量、取消/恢复与迟到过滤；应用设置跳转；密钥不进入Dart |
| 页面、聊天与计划表单 | 4–6小时 | 原布局、模式、目标、历史周数、重心/场景/伤病多选、流式正文与结束Markdown、玻璃控件、滚动与键盘 |
| 相机、相册和附件 | 2–3小时 | 复用原生权限/压缩/URI、Flutter预览/删除、返回和失败状态，不把大图base64反复传通道 |
| 历史、记忆与CSV闭环 | 3–5小时 | 历史查看/删除/重新选用、缓存与记忆既有行为、反馈细化、可编辑确认、原Room事务导入 |
| 五语、生命周期与回归 | 4–6小时 | 明暗、字体缩放、返回、旋转/后台/重进、取消/断流/恢复、附件与长回答、旧动作名称与备份一致 |

基础聊天6–10小时包含前两项的核心部分。完整范围加总16–24小时。真实服务兼容问题、复杂设备GPU差异或新增行为可能增加时间。

## 推荐边界

直接替换原AI标签页，避免新增独立“Flutter私教”入口。Kotlin保留模型配置、原提示词、媒体权限、Room、最终导入确认与请求所有权；Rust保留流协议处理；Flutter持有页面与临时交互状态。当前运行中的请求不因Widget重建而重复发送。

沿用固定全屏宿主、同一Navigator弹窗和统一玻璃材质：少量固定控件折射，长消息和列表轻量半透明，不为每条消息或每个token触发复杂背景采样。

## 单独计算的扩展

公开推理能力配置、Responses请求适配器及服务兼容验证约额外3–6小时；这是当前尚未启用的扩展，不应混同“把已有UI搬到Flutter”。只有服务公开提供的推理内容或摘要可展示，不能承诺完整内部推理。

本轮仅评估，没有变更私教页面，也没有请求真实AI服务。
