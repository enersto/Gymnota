# Flutter Liquid Glass 改造规范与固定宿主

更新：2026-11-08。本文件描述当前实现，替代此前将FlutterView搬入原生Dialog的方案。主要代码为lib/glass.dart、main.dart、embedded_catalog.dart及原生CatalogOverlayWindow.kt、EmbeddedCatalogView.kt、CatalogEnginePool.kt。

## 材质与分层

使用固定的liquid_glass_widgets 1.17.0，MIT及第三方许可在docs/third-party/liquid_glass_widgets。对照[Flutter库](https://github.com/sdegenaar/liquid_glass_widgets)与[Kyant原生实现](https://github.com/Kyant0/AndroidLiquidGlass/tree/kmp)，复用受控背板→模糊/折射→独立前景内容的原则，而非用白色描边冒充折射。

| 场景 | 实现 |
| --- | --- |
| 长列表 | solid半透明卡片，不为每行分配折射层 |
| 大详情面板 | 单层minimal磨砂，保持文字可读 |
| 少量详情操作 | GlassDialogAction完整premium，固定胶囊，文字独立 |
| 二级筛选 | GlassScrollableSegments连续轨道，standard轻量渲染 |
| 其他固定控件 | 共用适配器，按用途选择standard或局部premium |

GlassButton.custom默认LiquidOval不是长胶囊。详情按钮显式LiquidRoundedRectangle(height/2)，根据文字、缩放和空间计算有限宽高。上游全局自适应质量会限制显式premium，少量弹窗操作局部锁定质量；图形后端不支持时仍遵循上游能力回退。不得把整张长列表强制提升到premium。

## 已认可的二级菜单标准

一级用于页面导航，轮廓/选中区更明确，只点击切换；二级用于页面内筛选，视觉重量较轻。不能把两级做成完全相同的导航，也不能把二级拆成一串独立胶囊。

复用现有64dp连续轨道、4dp内边距、32dp外圆角、28dp选中圆角与自然文字宽度，色值跟随主题。保留上游点选后的滑块运动、释放回弹和收敛，不改硬切，不叠加第二套缩放/弹簧，不为所有页面虚构统一毫秒数。

横向拖动只滚动，点按才切筛选。视觉动画不应重复触发查询，回调按值去重。说明文字在轨道下面。验收覆盖末项可达、回弹后对齐、无残影/双份文字、列表斜向fling不切一级页、中英西德日与明暗主题。

## 固定全屏透明宿主：已实施

CatalogOverlayWindow保留旧类名，但不再创建原生详情Dialog、搬动FlutterView或为开窗改变其尺寸。管理页存续期间，同一view附着在当前窗口的固定全屏透明层；原AndroidView容器只标记列表位置。Dart CatalogViewport把列表布局到该矩形，主Navigator始终拥有完整窗口边界。

平时区域外透明、触摸透传，原生标题与菜单仍可用。根部原生浮动导航的64dp轨道和上下12dp间距保留，列表不覆盖它。详情在同一Navigator叠加遮罩、卡片和放大图，关闭仅移除路由。详情期间捕获整屏触摸，临时隐藏底层原生辅助功能，关闭后恢复；专用返回回调交给Dart。动画选择器使用一个全屏源Dialog放置原有居中卡片，详情不再另建窗口。

列表暂时隐藏用Offstage保持筛选/滚动；新catalogSession则重置，避免把动画选择器状态带入管理页。键盘和旋转的系统尺寸变化仍需正常响应，不等于为每次弹窗往返调整视口。

## 背景与媒体不再阻塞点击

Compose与Flutter是不同渲染表面，不能假设Flutter可持续逐像素采样原生菜单。平时根据宿主颜色和全局坐标重建列表区域渐变；原生Chrome背板只在空闲时PixelCopy，最多480px宽，后台PNG编码并预解码。

点击只用已准备且尺寸匹配的背板，不执行或等待截图；晚到背板留给下一次，不替换当前画面。列表区域重新绘制渐变，真实列表始终保持，DialogRoute统一画遮罩。无背板时原生区域仍可见并变暗，但可能没有相同的跨表面模糊。背景只在内存，不进个人备份。动画选择器叠在编辑Dialog上时，单窗口PixelCopy无法准确还原全部中间层，明确不用Activity近似截图覆盖它；保留实时原生层和统一变暗，跨表面模糊有限。

动图首帧在后台准备，详情可先显示已有缩略图，不等完整文件解码才出现。原1324个WebP规格不变；139个既有Flutter解码异常文件已无损改为独立关键帧。全量两循环测试与重编码工具继续保留。

## 生命周期、缓存与触摸

引擎预热包括实际目录、缩略图及两个折射按钮的绘制，不仅是加载字节码。准备完成后移除不可触摸的预热slot并暂停引擎。普通页面退出关闭旧Activity桥接、分离view，归还最多一个应用上下文引擎；新宿主重新绑定回调。未完成弹窗的强制退出销毁对应引擎，防止复用未结束路由。

固定层的Z值必须高于当前窗口已有子层（Compose DialogLayout有非零elevation），否则会被卡片压住、发白且收不到触摸；仅addView到末尾不足以保证顺序。

固定覆盖层的移除必须排到主线程队列，不能在系统正遍历detach子视图时同步修改同一父容器。释放幂等，缓存占槽时销毁多余引擎。缓存占RAM而非新增APK媒体；进程被杀后仍需冷准备。

触摸从列表区域开始后保持归属到手势结束，不能拖出区域就丢事件。详情打开后阻止底层标题与根tab触摸；关闭后恢复。原生和Dart返回要协调键盘、详情、放大和页面退出。选择动作仍回到原生编辑，个人命名、照片和Room保持原职责。

## 测试与后续页面

Native测试断言开关详情前后view父节点、宽高不变，普通状态透传原生触摸、详情拦截，缓存重进仍用同一引擎。Flutter测试覆盖全屏居中、无点击截图往返、区域定位、滚动、菜单末项与语言。实际入口还需检查根导航、搜索、动画选择器和使用动作到编辑。

性能诊断只保留有限帧计时。Dart提交帧不等于屏幕已经完成扫描显示；模拟器Debug数字也不是目标真机的保证。固定全屏缓冲区仍有内存/填充成本，持续滚动与冷启动需真机Preview/Release复核。

后续页面直接替换原入口，先确定背景来源、导航/滚动范围及内容/控件层，再用统一组件。不要在业务页重写一套玻璃参数，不增加“Flutter版”技术入口。AI迁移的流式、取消与公开推理显示准备见[专项说明](ai-coach-streaming-migration.md)，目前AI私教UI尚未替换。

## 历史页对齐（2026-11-09）

默认进入图表，沿用现有肌肉热力图及图形绘制；不再在页顶增加总统计、当前记录或查看备份按钮。设置负责恢复备份，历史仅读取当前Room；恢复后重新进入/前台恢复时刷新。

列表按原生的日期分组、橙色体重徽标、完成标记、单边标签、左右侧表格与传统目标值排版。按logType保留时长/次数/重量语义，不复制旧原生显示错误。采用扁平懒列表与16dp圆角solid卡片，不为每行增加背景模糊。日期/名称搜索只属于列表，切换后保留筛选、滚动和图表选择；大字体/窄屏的一级切换栏单独成行。图表数据表图标、日月与左右控件沿用统一玻璃组件，不改计算口径。

## 一级菜单、长标题与历史主入口（2026-11-09补充）

一级实际换项才触发Android VIRTUAL_KEY，尊重系统触感设置；不要在动画回调中重复触发。历史标题独占宽度，一级菜单在下方，高度随文字缩放。通用弹窗标题不采用单行ellipsis；类别移到下一行，极长标题允许滚动。已选动作名称也换行，选择器采用compact操作区以增加列表空间，仍保留可触摸尺寸。

历史主标签现直接内嵌Flutter，不再启动独立Activity。预热、Room失效推送、固定宿主和测量边界见[主历史宿主说明](flutter-history-host.md)。此项替代前文历史预览入口的描述。

## 当前统一规范

- 标题由 Flutter 绘制。按原生标题区使用状态栏下 24 dp、左右 16 dp、标题上下 8 dp。标题用 headlineSmall，保留粗体。正文从宿主主题取前景色 onBackground，控件底色从主色取得，避免用主色代替正文色。
- 一级导航使用连续玻璃通条，浅透主题底、较深的选中滑块和半透明白色高光边。选中与未选中同色，靠粗体和滑块区分。支持拖动和点选，实际换项触发系统触感一次。
- 二级筛选使用更轻的连续轨道，拖动选中滑块可换项，从滑块外横滑可浏览更多部位。保留回弹，页面纵向拖动交给内容列表。
- 内容卡片使用轻量半透明表面。大弹窗采用单层磨砂，只给少量固定操作加完整折射。长标题换行，极长标题可滚动。保留系统字体缩放和触摸尺寸。
- 采用固定宿主和同一导航层展示详情。非模态时向原生导航透传触摸，模态关闭后恢复。允许后台预热，避免点击时等待截图。持续滚动和流式正文避免逐行或逐字重建折射层。

## AI 私教 Flutter 首轮预览

从 Kotlin 页面提取标题、目标表单、历史周数、自由对话输入和流式开关，复用共享玻璃组件和现有五语标签。调试构建的原私教页提供临时预览入口。输入和开关状态为预览本地状态，发送按钮暂时禁用。

完整替换前需要将会话状态与命令接入现有 ViewModel，包括配置跳转、训练重心、场景与伤病、多模态附件、历史管理、流式回复和取消、反馈细化及 CSV 确认。

## 主导航与私教

主导航依次为打卡、历史、动作、AI 私教、设置。「动作」承接原动作管理入口。根标签允许两行文字。动作库原生通条沿用 Kyant 的背景折射和独立文字层，Flutter 通条、选择框与私教主按钮共用折射设置。动作目录卡片复用旧个人卡片的 16 dp 圆角、12 dp 内边距、52 dp 缩略图和细边界，列表保留轻量表面。

私教主入口通过固定宿主嵌入 Flutter，使用根 Activity 的 MainViewModel。宽版历史建议用柔和的主题磨砂底色，「当前目标」使用轮廓、浮动标签和编辑图标。现有 Compose 私教源码保留于 AICoachScreen.kt。需要回落时，将 MainScreen.kt 中的 useFlutterCoach 切为 false 后重新构建。
